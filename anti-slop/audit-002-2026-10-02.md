# Anti-Slop UI Audit 002

Date: 2026-10-02

Scope: targeted static review of the web app based on the user's screenshot and the requested dark-mode, dashboard-navigation, and owner stock-opname workflows. No application source files were modified. The working tree contains unrelated user changes, which were preserved.

Priority key: HIGH = Hard Gate; MEDIUM = Purpose-Gate; LOW = Quality Lock.

## Findings

### 1. HIGH - Dark mode leaves fixed dark text on dark surfaces

Rules: R-25 Color Contrast; R-34 Every Theme You Ship Must Work.

Evidence: the screenshot shows dark foreground text on the dark stock-opname screen. The shared stylesheet still hard-codes dark text colors, including `body, .workspace, .pos-workspace { color: #111827; }` in `frontend/app/globals.css`, while dark surfaces use navy/slate backgrounds. Dark-mode overrides cover selected components, not all text-bearing controls and pages.

Why it matters: dark-on-dark text has insufficient contrast and makes labels and stock details difficult to read. This is visible on the supplied opname screen and the same shared rules can affect other routes.

### 2. LOW - Stock dashboard is embedded in the owner's sales dashboard, not navigable as an inventory destination

Rule: R-05 Layout & Page Structure; C-3 Content-Driven Composition.

Evidence: `frontend/app/dashboard/page.js` renders owner sales metrics and charts, then conditionally appends `WarehouseDashboard` when `data.owner_stock_dashboard` exists. In `frontend/app/components/AppShell.js`, the general sidebar has one `/dashboard` item under `UTAMA`, with no distinct stock-dashboard destination under `PRODUK & INVENTORI`.

Why it matters: sales and inventory answer different operational questions. Combining them creates a long mixed-purpose page, and store users do not have a separate stock-dashboard destination matching the requested information architecture.

### 3. HIGH - Owner stock opname is restricted to warehouses in the owner's assigned branch

Rule: R-26 Interactive Elements.

Evidence: `frontend/app/inventory/opname/page.js` loads warehouses from `/inventory/warehouses` without a branch selection. In `backend/src/routes/inventory.js`, that endpoint defaults to `req.user.branch_id` for an owner unless a specific `branch_id` is passed. The existing `/inventory/warehouses/all` endpoint already returns active warehouses across branches for owners, but the opname page does not use it or provide a branch selector.

Why it matters: the existing warehouse dropdown cannot select another store/gudang, so an owner cannot perform the requested opname outside the account's assigned branch.

## Audit limits

- This was a source review plus the user's supplied screenshot, not a full browser walkthrough.
- I did not run the app, measure every color pair, or exercise role-specific navigation and opname save flows.
- Findings are limited to the three requested areas; no conclusion is made about unrelated pages or interactions.
